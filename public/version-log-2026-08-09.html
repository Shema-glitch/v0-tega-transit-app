Scaling & observability batch

2026-08-09 · backend repo v0-tega-transit-app · deployed on Render — tega-transit-api.onrender.com

This batch makes the API ready for hundreds of simultaneous users: static GTFS data is now cached in memory (and Redis), every request is counted into a per-endpoint metrics ring the admin watches live, and the cache headers actually work. Read the For frontend developers section below — it changes how you should fetch.

What shipped

APIPer-endpoint load metrics

Every /api request is counted in middleware; handlers record status + latency. New GET /api/admin/metrics (admin-only) + a live Load section in the console: requests/min, p50/p95 latency, 429 trips, SSE gauge, cache hit rate.

APITTL cache + single-flight

Shapes, sequences, search, routes are served from memory (1h–1d); arrivals get a 5s micro-cache. Concurrent callers share one Supabase query per key. Failures are never cached.

SHAREDRedis L2 NEW

Optional REDIS_URL: cache warmth survives restarts + spans instances, and the per-IP rate limiter becomes shared. Degrades to in-memory automatically when unset.

SHAREDLive store pub/sub NEW

Broadcast pings + incident reports are shared across instances via Redis pub/sub (tega:live-vehicle / tega:incident). SSE subscribers on any instance see vehicles reported anywhere. Idempotent applies, backoff reconnect, silent no-op without Redis. The Load section shows redis shared · pub/sub.

SHAREDCache headers work now

Static endpoints carry max-age (browser cache) + s-maxage (CDN-ready). Returning riders skip the server entirely.

APISSE cap raised

Concurrent SSE connections: 100 → 250, overridable with MAX_SSE_CONNECTIONS. Over the cap → 503.

APIBuild hardening

Type errors now fail the Render build instead of shipping silently. Public status page is read-only — checks + SSE monitor moved behind admin auth.

APILoad alerts NEW

The Load section flags spikes automatically: request rate over 120/min or rate-limit trips over 10 in the window trips an amber/red alert with a recent-episodes list. Thresholds overridable via LOAD_ALERT_RPM_THRESHOLD / LOAD_ALERT_429_THRESHOLD.

AUTHAdmin auth: public redirect + TOTP NEW

Magic-link emails now point at ADMIN_PUBLIC_URL (set it to the Render URL) instead of wherever the request came from — no more localhost bounce on confirmation links. New addresses get a one-time confirmation email before codes flow (the login page explains it). Admins can enroll a Google Authenticator second factor in the console's new Settings tab; sensitive actions (stop writes, maintenance toggles, admin invite/revoke, suggestion approval) then need a fresh code, with a 5-minute grace after identity confirmation.

CURATORSCurator tier: merge, undo, roles NEW

A second admin role for vetted map editors (migration 0014). Curators get a Map & Stops section: full stop list with status/hub badges, edit (rename/move/hub), merge with a dry-run preview of the exact affected stop_times + pending suggestions, one-shot undo from a snapshot journal, and server-side duplicate detection feeding "Suggested merges". Merged stops redirect to their survivor everywhere — old cached ids and deep links keep working. Hide/restore and role grants stay admin-only. Roles are re-read every request, so a revoke is immediate; the sidebar hides People / Endpoints / Load / Guide for curators.

Also live from earlier batches: durable maintenance flags + auth audit log (migrations 0010–0011), 90-day uptime bars (/api/uptime, 0012), admin invites (0009), admin console rebuilt on shadcn with a sidebar.

For frontend developers — consuming the API at scale

FRONTEND 1. Cold starts still exist (free tier)

Render's free instance sleeps after ~15 min idle; the first request after a gap can take 20–50s. Keep the layered strategy:

  1. Fire GET /api/health on mount as a wake-up ping (don't await it).
  2. Render skeletons immediately — never a blank map.
  3. Serve the bundled kigali_stops.json snapshot while the API wakes.
  4. Show a "waking the server…" banner when the first request exceeds 5s.

FRONTEND 2. Cache-aware fetching (the big one)

Static data is now cached server-side AND in your users' browsers:

EndpointFresh forWhat this means for you
/api/routes, /api/gtfs/routes, /api/search/suggest1hDon't poll. Fetch once per session and reuse.
/api/routes/{id}/shape, /sequence1 dayCache per route forever; invalidate on a GTFS update.
/api/stops, /api/gtfs/stops, /api/gtfs/hubsin-memory snapshotFetch once per session.
/api/stops/{id}/arrivals5s micro-cachePolling every 30–60s is plenty; 5s is the floor.
/api/vehicles/liveuncached (live)Polling fallback only — prefer SSE.

Search: debounce 300ms, cache suggestions by query in React Query (staleTime ≥ 1h). Server-side, the same query from 100 users costs one PostGIS call.

FRONTEND 3. SSE — connect once, scope, reconnect

const sse = new EventSource(
  `/api/realtime/sse?lat=${lat}&lng=${lng}&radius=3000&routes=${routes.join(',')}`
)
sse.addEventListener('message', (e) => {
  const { type, vehicles } = JSON.parse(e.data)
  if (type === 'vehicle:update') vehicles.forEach((v) => updateMarker(v.id, v))
})
sse.onerror = () => setTimeout(() => sse.close(), 5000) // let EventSource auto-reconnect
  • Deltas only carry id, lat, lon, brg, spd — merge, don't replace.
  • Scope with routes= and direction= to cut payloads for a stop-watch view.
  • 503 from SSE = connection cap (250). Retry with exponential backoff (1s → 2s → 4s…), and fall back to polling /api/vehicles/live.
  • One shared hub feeds every client — your connection count doesn't multiply DB load.

FRONTEND 4. Respect rate limits

Per IP, per minute: 120 reads (per route-group), 30 writes. On a 429, honor Retry-After and back off. The headers X-RateLimit-Limit / X-RateLimit-Remaining tell you where you stand. A healthy session (SSE + stop lookups + a search every few seconds) is a tiny fraction of this — only aggressive polling or retry loops trip it.

FRONTEND 5. 503 ≠ broken — read the body

Two kinds of 503:

  • Maintenance disable — the admin turned an endpoint off mid-incident. Body: { error, reason, since }. Show the reason to riders; retry every 15–30s.
  • SSE capacity — connection cap. Back off + poll fallback.

SHARED 6. Uptime bars on the public status page

The status page reads GET /api/uptime — 90 days of per-endpoint daily buckets (green/amber/red/gray). If you build your own status UI, use this endpoint; the "re-run checks" + SSE monitor buttons are admin-only now (POST /api/admin/diagnostics/check) — never call them from the public app.
