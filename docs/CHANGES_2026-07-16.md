# Changes — 2026-07-16

Simple version of what changed tonight. (Full technical writeup is in
`docs/PROJECT_LOG.md`, dated entry for today.)

## What I did

Fixed the two API inconsistencies that were flagged as "risky to change"
last session — turned out they were safe, so I just did them.

1. **Bus/route IDs are now consistent.** Some parts of the API said
   `"route-101"`, others said `"101"`. Everything now says `"101"`.

2. **Coordinate field names are now consistent.** Some endpoints used `lat`/`lng`,
   others `lat`/`lon`, others `latitude`/`longitude`. Everything now uses
   `lat`/`lon`.

3. Same cleanup for incident reports (route/vehicle/type field names) and
   for stops/hubs (added a `type` field so it's clear what kind of place
   each result is).

## Why it was safe to do

The frontend app already has code that handles multiple versions of these
field names at once (I confirmed this by reading their own project log) —
so switching the API to the clean/consistent version doesn't break anything
on their end.

## How I checked it actually works

- Type-checked the whole project — clean.
- Ran it locally and sent a fake "bus location" update using the *old*
  `"route-101"` format, then confirmed the live API correctly picked it up
  and returned it in the *new* `"101"` format.
- Watched the live stream directly and confirmed buses, incidents, and
  viewer counts all come through with the new field names.
